The landed source increment has one production semantic owner. The existing `PPPreprocessingSession` and typed phase-3 `PPTokenBuffer` feed `parse_pa10_ast`, whose `PA10Ast` retains node identity, token/source provenance, qualified-name components, decoded literal facts, and child order. One `PA11SemanticModel` owns canonical `TypeId`, `BindingId`, `ScopeId`, `NamePath`, declaration facts, lookup, function types, and constant values. `builtin_kind` classifies only an exact direct `IdExpression` with no token, global qualifier, prefix, or extra name component; qualified, global-qualified, parenthesized, and nonexact prefix forms remain ordinary source shapes. The exact implementation-reserved spellings are recognized before ordinary lookup, so user shadowing of those reserved names is not claimed as a PA12 feature; the checked-in builtin-prefix control remains ordinary lookup.

The call owner validates a two-child call node and an `ArgumentList` or `ParenArgumentList` before dispatch. `__builtin_constant_p` requires exactly one argument, semantically validates that operand first, and folds only when its resulting type is integral; unknown names, invalid operators/conversions, and nested semantic failures escape before folding. The repair replaces the prior broad `runtime_error` catch with the typed `NonConstantExpression` fold-failure boundary, so a valid but unpropagated integral expression becomes the required typed zero while malformed ASTs and invalid model/type errors remain failures. `SemanticTailGuard` transactionally restores the four PA12 arena tails—facts, child IDs, conversion facts, and semantic-name components—on exception and discards them immediately after the operand type is known on success, preventing unreachable operand facts from accumulating in the dump path. A semantically valid nonintegral operand is not folded and produces the typed zero; that behavior is outside the required propagated-integral fold set and was not broadened here.

The builtin result is one model-owned `SemanticFactKind::Literal` with canonical `int`, prvalue category, decoded value `1` or `0`, and `ExprInfo::integer_zero` set for the known-zero result. The repair carries that typed zero status through `conversion_for` from context conversion, built-in conversion, casts, and call candidate scoring; raw AST integer-zero recognition remains unchanged. Thus a known-zero intrinsic result preserves its source conversion provenance while working in pointer returns, pointer/nullptr contexts, pointer comparisons/conditionals, and pointer arguments. `__builtin_abort` lazily publishes one model-owned function `BindingId` with canonical `void ()` type, records it on the call fact with the global selected scope, and lets the cold renderer produce the stable `callee __builtin_abort function of () returning void` line. No lookup binding or duplicate abort fact is created.

PA11 `SpecFact::is_constexpr` is copied into the model-owned `DeclarationFact` during simple-declaration processing. PA11 adds the declaration cv fact and publishes integral constant values; PA12 retargets only a declaration-owned constexpr complete-object literal after recording the original context conversion. Pointer/null literal output therefore reflects the target object type without discarding the source conversion, while ordinary `const` declarations and nonliteral expression facts are untouched. The renderer walks typed fact IDs, binding/type IDs, source token provenance, and cold presentation helpers only at the requested dump boundary; it does not reparse rendered text or reconstruct semantic identity from text.

The local transaction therefore has a precise four-vector scope, not whole-arena invalidation. AST arity, candidate vectors, and evaluator recursion remain local to the expression being processed.
